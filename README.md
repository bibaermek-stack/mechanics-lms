# Механика AI LMS

Магистрлік диссертацияға арналған, жасанды интеллект негізіндегі қашықтықтан оқыту платформасы.

**Тақырып:** «Механиканы қашықтықтан оқыту жағдайында студенттердің ақпараттық-коммуникативтік құзыреттілігін қалыптастыруға арналған жасанды интеллект негізіндегі білім беру платформасы»

Бүкіл интерфейс — батырмалар, мәзірлер, хабарламалар, дашбордтар, викториналар, ойындар, сертификаттар — толығымен **қазақ тілінде**. Бастапқы код пен түсініктемелер ағылшын тілінде жазылған (халықаралық әзірлеу тәжірибесіне сай).

## Жобаны іске қосу

```bash
cd mechanics-lms
npm install
cp .env.local.example .env.local   # қажет болса, кілттерді толтырыңыз
npm run dev
```

`http://localhost:3000` мекенжайын ашыңыз. `.env.local` файлын толтырмасаңыз да, платформа **толық жұмыс істейді** — барлық деректер localStorage-те мок түрінде сақталады, ал AI тьютор дайын қазақша жауаптар қайтарады.

> **Кеңес:** егер `npm run build` кезінде түсініксіз қатеге (мыс., "Bus error" немесе бос output) тап болсаңыз, бұл әдетте желі/диск проблемасынан кейбір пакеттің (жиі `@next/swc-*`) жартылай жүктелуінен туындайды. Шешімі: `rm -rf node_modules package-lock.json && npm install` арқылы толық қайта орнатыңыз.

Өндірістік құрастыру (CI оны әр өзгерістен кейін тексереді):

```bash
npm run build
npm run start
```

## Мок режим vs. нақты сервистер

Жоба **"нақты SDK кодтары + мок fallback"** тәсілімен құрылған (`src/lib/supabase/client.ts`, `src/lib/dataStore.ts`, `src/lib/ai.ts`, `src/lib/googleWorkspace.ts`):

- **Supabase:** `NEXT_PUBLIC_SUPABASE_URL` және `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` толтырылса, тіркелгілер, рөлдер, оқытушы↔студент байланысы және барлық оқу жазбалары (викторина, ойын, БӨЖ, бағалау, сертификат, диагностика) Supabase-те сақталады; қолжетімділікті дерекқордың RLS саясаттары басқарады (`supabase/migrations/`, 0001–0011, қадамдар — `supabase/README.md`). Кілттер жоқ болса — браузердің `localStorage`-і. Бұл режимде оқытушы аналитикасы **демо топты** көрсетеді және экранда бұл анық жазылады.
- **AI:** `NEXT_PUBLIC_AI_PROVIDER=openai` немесе `gemini` қойып, тиісті API кілтін (`OPENAI_API_KEY` / `GEMINI_API_KEY`) толтырсаңыз, сұраулар нақты моделге жіберіледі. Кілт жоқ болса немесе провайдер қатесі болса, жүйе автоматты түрде дайын қазақша жауаптарға (mock) ауысады — демо ешқашан "бұзылмайды".
- **Google Workspace:** `GOOGLE_CLIENT_ID`/`SECRET` толтырылса, OAuth логин, Sheets оқу және Drive тізімдеу нақты жұмыс істейді (`src/lib/googleWorkspace.ts`, `/api/auth/google/callback`, `/api/google/sheets`). Кілттер жоқ болса — мок жолдар қайтарылады.

Толығырақ орнату қадамдары `DEPLOYMENT.md` файлында.

## VR/AR зертханалық орта

`/vr-lab` бетінде студент зертхананың **ішіне кіріп**, PASCO жабдығының қасында тұрып
тәжірибе жүргізе алады. Орта үш режимде бірдей жұмыс істейді:

| Режим | Не қажет | Қалай басқарылады |
|---|---|---|
| **VR** | Meta Quest, Pico, SteamVR — браузерден | Контроллер сәулесімен үстел пультінің батырмалары |
| **AR** | Android + Chrome немесе Quest браузері | «AR» батырмасы → нақты үстелді түртіп, зертхананы қою |
| **Экран** | Ешнәрсе | Тінтуірмен қарау, W/A/S/D-мен жүру, батырмаларды шерту |

### Технологиялық бөліну

- **A-Frame (WebXR)** тек *бөлмеде болуға* қатысты нәрсеге жауап береді: XR сессиясы,
  камера, контроллерлер, AR-дағы `ar-hit-test` арқылы бетті табу.
- **three.js** барлық затты салады: зертханалық үстел, 1,2 м динамикалық рельс, шкив,
  штатив, көлбеу жазықтық, серіппе, күш векторлары, энергия бағандары
  (`src/lib/vr/three-models.ts`).
- **PASCO құрылғылары** — нақты сканерленген GLB файлдары (`public/models/*.glb`).
  Олар A-Frame-нің `gltf-model` компонентімен емес, `src/lib/vr/pasco-loader.ts` арқылы
  жүктеледі: файлдар meshopt-пен қысылған, ал декодер сырттан емес, `three` пакетінен
  алынады — яғни CDN-ге бірде-бір сұрау кетпейді.
- **Мәтін** A-Frame-нің `<a-text>` компонентімен емес, canvas-текстура арқылы салынады
  (`src/lib/vr/canvas-panel.ts`): `<a-text>` шрифт атласын CDN-нен жүктейді және онда
  кириллица, оның ішінде қазақ әріптері (ә, ғ, қ, ң, ө, ұ, ү, і) жоқ.

### Тәжірибелер

| Тәжірибе | Зертханалық жұмыс | Не өлшенеді |
|---|---|---|
| Бірқалыпты және үдемелі қозғалыс | №1, №2 | x, v, a, жүрілген жол |
| Ньютонның ІІ заңы және үйкеліс | №3, №4 | a, v, жіптің керілуі, үйкеліс күші |
| Көлбеу жазықтықтағы энергия | №6 | h, v, Eₚ, Eₖ, үйкеліс жылуы Q |
| Математикалық маятник | №7 | θ, ω, теориялық және өлшенген период |

Физика тұрақты қадаммен (2 мс) интегралданады — жұмыс үстеліндегі симуляциялармен бірдей
қозғалтқыш логикасы. Маятник кіші бұрыш жуықтауымен емес, толық `θ̈ = −(g/L)·sin θ`
теңдеуімен есептеледі, сондықтан θ₀ = 15° кезінде өлшенген период (1,424 с) теориялық
мәннен (1,419 с) заңды түрде сәл үлкен болып шығады — бұл тәжірибенің үшінші тапсырмасы.

Параметрлер екі жерде де өзгереді: беттегі жүгірткілерде және гарнитураның ішіндегі
үстел пультінің «−»/«+» батырмаларында. Екеуі де бір күйге жазады, сондықтан көзілдірікті
шешудің қажеті жоқ.

## Арена — физикалық футбол

`/arena` бетіндегі 2D командалық ойын. Ойыншылар — дөңгелек денелер, доп та дөңгелек;
бәрі бір физика қозғалтқышында қозғалады. Ойын жанры ретінде Haxball-ға ұқсас, бірақ
коды толығымен осы жобада жазылған — сырттан ешбір репозиторий көшірілмеген.

### Физикасы

Барлық шама СИ жүйесінде: метр, секунд, килограмм. Бұл әсемдік үшін емес — экрандағы
сандар сабақтардағы формулалармен тікелей салыстырылады.

| Заң | Кодтағы орны |
|---|---|
| Ньютонның ІІ заңы | Жүру күші `F = 780 Н`, үдеу `a = F/m` (`physics.ts` → `step`) |
| Ньютонның ІІІ заңы | Тебу — импульс: доп `J/m_доп` алса, ойыншы қарама-қарсы бағытта `J/m_ойыншы` жоғалтады (`tryKick`) |
| Импульстің сақталуы | Соқтығыс `j = −(1+e)·vₙ/(1/m₁+1/m₂)` импульсімен шешіледі; екі денеге шамасы тең, бағыты қарама-қарсы импульс беріледі, сондықтан **Δp = 0** дәл орындалады (`collide`) |
| Серпімді/серпімсіз соққы | Серпімділік коэффициенті `e`: доп 0,85, ойыншы 0,35. e &lt; 1 болғанда кинетикалық энергия кемиді, ал импульс кемімейді |
| Үйкеліс | Жылдамдықтың экспоненциалды кемуі `v(t) = v₀·e^(−k·t)`: доп үшін k = 0,42 с⁻¹, ойыншы үшін 4,2 с⁻¹ |

Экранның астындағы «Физика» панелі әр соқтығыстың **алдындағы және кейінгі импульсін**
көрсетеді. Тірі мәндер емес, дәл соқтығыс сәтінде бекітілген мәндер — әйтпесе борттан
серпіліс пен үйкеліс (сыртқы күштер) заңды бұзғандай көрінер еді. Дәл сол тәсіл
6-сабақтың импульс симуляциясында да қолданылған.

Ойыншы 72 кг, доп 0,44 кг — айырмашылық 160 есе. Сондықтан ойыншы допқа соғылғанда доп
ұшып кетеді, ал ойыншының жылдамдығы шамалы ғана өзгереді: бұл дәл импульс сабағында
талданатын асимметрия.

### Онлайн бөлмелер

Сыныптастарыңмен ойнаудың екі жолы бар, ал бет қайсысы қолжетімді болса, соны таңдайды.

**A. Ойын сервері (ұсынылады).** `server/index.ts` — Node + WebSocket сервері. Ол
Vercel-де тұра алмайды (serverless функциялар жадта қалмайды), сондықтан бөлек
орналастырылады — мысалы **Railway**-ге. Артықшылығы: төреші — сервер, яғни матч
ешкімнің ноутбукі жабылғанда қайта басталмайды және ешкім допты басқалардан бір кадр
бұрын көрмейді. Сервер физиканы `src/lib/arena`-дан импорттайды — соқтығыстың екінші
көшірмесі жазылмайды, әйтпесе олар бірінші өзгерісте-ақ бір-бірінен алшақтар еді.

Қосу: Railway-де build `npm run build:server`, start `npm run start:server`, содан соң
веб-деплойға `NEXT_PUBLIC_ARENA_SERVER=wss://…` айнымалысын қойып, қайта деплой жасау.
Толық қадамдар — `DEPLOYMENT.md`, 7-бөлім. Серверге дерекқор да, құпия кілт те қажет
емес.

**B. Supabase Realtime.** Сервер жоқ, бірақ Supabase кілттері бар болса, бөлме — Realtime
арнасы, ал төреші — ойыншылардың бірі: бірінші қосылған адамның браузері физиканы
жүргізіп, күйді 20 Гц-пен таратады. Екінші деплой қажет емес, бірақ төреші шықса есеп
қайта басталады.

Екеуі де жоқ болса, боттарға қарсы жаттығу бәрібір толық жұмыс істейді.

Сервер 20 Гц жиілікпен күй жіберсе, экран 60 Гц салады — сондықтан клиент әр денені
өз жылдамдығымен келесі кадрға дейін жалғастырып сызады (`extrapolated`). Бұл тек
сызуға әсер етеді, симуляцияға қайта берілмейді.

### Сабақтардағы орны

Ойын 3, 4, 5 және 6-сабақтардың «Ойын» табында 11-ші режим болып шығады — динамика, үш
заң, энергия және импульс. Қалған сабақтарда көрсетілмейді: онда соқтығыс физикасының
оқытатыны жоқ.

## Ойындар, күнделікті сынақ және жетістіктер

Сабақтың «Ойын» табында және бөлек `/games` бетінде **15 ойын түрі** бар. Әр сабақта олардың бәрі бірдей емес: ойын тек сабақтың материалы жеткілікті болғанда ғана көрсетіледі (бос тақта ашылмайды).

| Топ | Ойындар |
|---|---|
| Терминдер мен ұғымдар | сәйкестендіру, жады карточкалары, сүйреп апару, флэш-карточкалар, кроссворд, сөз табу, бос орынды толтыр, сұрыптау, айналмалы дөңгелек |
| Жылдамдық пен ойлау | жылдам жауап, **Шын ба, өтірік пе?**, **Ретке келтір** (бейне-дәрістің оқиғаларын ретімен), **Есеп-блиц** (формула бойынша 8 есеп) |
| Физика | **Снаряд атысы** (2–3 сабақ), Арена (3–6 сабақ) |

- **Әділ дуэль.** Әр тақта — `(сабақ, seed)` функциясы (`src/lib/rng.ts`), сондықтан дуэльде екі ойыншыға бірдей тақта түседі.
- **Викторина банкі.** Әр сабақта 15 сұрақ, әр тапсыруда 10-ы кездейсоқ таңдалады (`drawQuiz`). Сандық сұрақтардың жауабы `src/data/formulas.ts` формулалар банкінен есептеледі және тесттермен тексеріледі; оқытушы сабақты өзгертсе, сабақ беті мен `/games` бетіндегі викторина, ойындар және күнделікті сынақ өзгертілген мазмұнды пайдаланады. Дуэль тақталары әрқашан бастапқы (өзгертілмеген) мазмұннан құрылады.
- **Снаряд атысы** (`src/lib/projectile.ts`): бұрыш пен жылдамдықты таңдап, Жерде, Айда, Марста және Юпитерде нысанаға атасың. 5 раунд, раундына 4 атыс (100/70/45/25 ұпай); 3-раундтан бастап жолда қабырға тұрады — жалпақ атыс өтпейді, көтере ату керек. Болжамды (R, H, T және нүктелі траектория) қосуға болады, бірақ раунд ұпайы ×0,7. Раундтан кейін `R = v²·sin 2θ / g` формуласы сол атыстың сандарымен есептеліп көрсетіледі.
- **Күнделікті сынақ** (`/daily`, `src/data/daily.ts`): күн сайын 5 сұрақ, әр бес түрлі сабақтан бір-бірден. Сұрақтар тек күннен есептеледі, сондықтан сол күні барлық студентке бірдей, ал келесі күні басқа. Күніне бір рет; ұпай — дұрыс жауаптың үлесі, уақыт есептелмейді.
- **Деңгей, серия, жетістіктер** (`src/lib/engagement.ts`): деңгей XP-тен (0, 100, 400, 900 … 8100; 10 деңгей), серия — кез келген жазба (викторина, ойын, БӨЖ, бағалау, диагностика) жасалған күндерден студенттің өз күнтізбесі бойынша. Кеше белсенді болса, серия әлі тірі, бірақ «бүгін түнде үзіледі» деп ескертіледі. 21 жетістік профиль бетінде прогресспен көрсетіледі. Бәрі жазбалардан **есептеледі**, бөлек сақталмайды: дерекқорды өзгертудің қажеті жоқ, демо және Supabase режимінде бірдей жұмыс істейді.
- **Бағаға әсері.** Күнделікті сынақ — жаттығу, оқу жұмысы емес: қорытынды бағадағы «ойындар» компонентіне кірмейді (`isLessonGame`). XP ережесі өзгермеген (әр сабақ пен ойын түрінің ең жақсы нәтижесі × 0,5), сондықтан сынақ XP-ке ең көбі 50 қосады.

## Зерттеу аналитикасы: бастапқы және қорытынды диагностика

Диссертацияның тезисі — өзгеріс: студенттер курстан кейін курстың алдынан гөрі көбірек біледі. Өзгерісті өлшеу үшін бір тест екі рет тапсырылады.

- **Тест** (`/diagnostic`, сұрақтар — `src/data/diagnostic.ts`): 20 сұрақ, әр сабақ тақырыбынан екеуі, бастапқы және қорытынды кезеңде **бірдей**. Сұрақтар сабақ викториналарының сұрақтары емес — викторинаны дұрыс болғанша қайта тапсыруға болады, сондықтан олармен өлшесек, курс материалын жаттағанды өлшер едік. Дұрыс жауап көрсетілмейді.
- **Ережелер** (дерекқор деңгейінде, `0011_diagnostics.sql`): әр кезеңге бір тапсыру; жазбаны өзгертуге болмайды; қорытынды тест бастапқысынсыз жазылмайды. Қорытынды тест студент 8 сабақтың викторинасын тапсырғаннан кейін ашылады (`POST_UNLOCK_LESSONS`).
- **Оқытушыға** `/teacher/analytics` бетінде — топ бойынша бастапқы және қорытынды орташа ± SD, өсім, Hake нормаланған өсімі, жұптасқан t-критерийі, Cohen d_z; эксперименттік және бақылау топтарын таңдап салыстыру (Welch t-критерийі, өсімнің айырмасы, топтардың бастапқы деңгейін тексеру). Нәтижені Excel-ге CSV ретінде жүктеуге болады.
- **Назар аударыңыз:** сұрақтарды бірінші студент бастапқы тестті тапсырмай тұрып өзгертіңіз — кейін өзгертсеңіз, бұрынғы және кейінгі ұпайлар салыстырылмайды. Топтар кездейсоқ бөлінбесе және студент саны аз болса, p-мән — алдын ала көрсеткіш қана.
- Сервер қосылмаған (демо) режимде бет **ойдан құрастырылған топты** көрсетеді және бұл экранда жазылады; оны зерттеу нәтижесі ретінде пайдалануға болмайды.

Формулалар `src/lib/stats.ts` ішінде, `src/lib/stats.test.ts` тесттері тәуелсіз есептелген мәндермен салыстырады.

## Офлайн режим (PWA)

Сайтты телефонның басты экранына қосуға болады (manifest + иконкалар). `public/sw.js` қолданбаның кодын және студент ашқан беттерді сақтайды — олар интернетсіз де ашылады, ал ашылмаған бет үшін «Интернет жоқ» беті шығады. Supabase-тен келетін деректер, AI жауаптары және сабақ бейнелері кэшке **түспейді**: офлайн ашылған бетте жаңа деректер жүктелмейді. Service worker тек production құрастыруда тіркеледі.

## Педагогикалық негіз

- **ADDIE моделі:** Analysis (қажеттілікті талдау) → Design (Блум таксономиясы бойынша нәтижелер, рубрика) → Development (10 сабақ, AI, ойындар) → Implementation (Next.js платформа) → Evaluation (құзыреттілік бағалау, аналитика).
- **Блум таксономиясы:** әр сабақта алты деңгей де (`Есте сақтау → Түсіну → Қолдану → Талдау → Бағалау → Жасау`) `src/data/modules.ts` файлындағы `bloom` өрісінде беріледі және сабақ бетінде көрсетіледі.
- **Ақпараттық-коммуникативтік құзыреттілік моделі:** 10 критерийлі рубрика (`src/lib/competency.ts` → `RUBRIC_CRITERIA`), 5 деңгей (Бастапқы → Сарапшы).
- **Қорытынды баға формуласы:** салмақталған 10 компонент (`src/lib/competency.ts` → `GRADE_WEIGHTS`): бейне 10%, викторина 20%, ойындар 10%, БӨЖ 20%, Google Forms 15%, AI белсенділігі 10%, форум 5%, портфолио 5%, жоба 5%, рефлексия 5%.
